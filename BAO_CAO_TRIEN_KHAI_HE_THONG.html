CHƯƠNG 1: TỔNG QUAN ĐỀ TÀI VÀ KIẾN TRÚC TỔNG THỂ

1.1. Bối cảnh và Mục tiêu

Trong ngành dịch vụ ẩm thực (F&B), việc ứng dụng công nghệ thông tin vào khâu quản lý bàn, tiếp nhận đơn gọi món (order) và thanh toán là yếu tố sống còn giúp nâng cao năng suất phục vụ. Đối với học phần Triển khai và Quản trị Hệ thống Phần mềm, đề tài Đề 12: Hệ thống Quản lý Nhà hàng / Order được triển khai hoàn chỉnh bằng công nghệ Container hóa Docker Compose kết hợp các giải pháp DevOps tiên tiến: Nginx Reverse Proxy, Prometheus, Grafana, Loki, Promtail và Hardening bảo mật.

1.2. Mô hình phân chia 3 Mạng độc lập (Network Isolation)

Toàn bộ 10 container dịch vụ được cô lập vào 3 phân vùng mạng Docker riêng biệt:

  • frontend-net: Chứa Nginx, Web App và pgAdmin để phục vụ truy cập người dùng qua cổng 80/443.
  • backend-net: Chứa Web App, pgAdmin và CSDL PostgreSQL 16. Cổng 5432 của CSDL hoàn toàn không xuất ra ngoài host.
  • monitoring-net: Chứa Prometheus, Grafana, cAdvisor, Node Exporter, Loki và Promtail phục vụ giám sát và lưu trữ log.

CHƯƠNG 4: NGINX REVERSE PROXY VÀ BẢO MẬT SSL/HTTPS

Nginx đóng vai trò Edge Gateway tiếp nhận cổng 80 và 443:

  • Chuyển hướng 301: Mọi request HTTP vào cổng 80 đều tự động chuyển sang HTTPS cổng 443.
  • Chứng chỉ SSL tự ký: Thuật toán RSA 2048-bit, hỗ trợ TLSv1.2 và TLSv1.3.
  • Security Headers: HSTS, CSP, X-Frame-Options (chống Clickjacking), X-Content-Type-Options (chống MIME-sniffing).
  • Rate Limiting: Giới hạn 10 request/giây/IP chống tấn công DoS và Brute-force.

CHƯƠNG 5: HỆ THỐNG GIÁM SÁT PROMETHEUS & GRAFANA

Prometheus định kỳ 5s cào metrics từ 4 targets (đều đạt trạng thái UP 100%):

  • restaurant-web:5000: Đo tổng request HTTP và thời gian xử lý.
  • cadvisor:8080: Giám sát CPU/RAM của từng Docker Container.
  • node-exporter:9100: Giám sát tải phần cứng máy chủ Linux.
  • prometheus:9090: Giám sát hoạt động của chính máy chủ Prometheus.

CHƯƠNG 6: HỆ THỐNG LOG TẬP TRUNG LOKI & PROMTAIL

Promtail tự động đọc log JSON từ Docker daemon đẩy về Loki. Minh chứng 3 câu truy vấn LogQL:

1. Lọc log ứng dụng web:
{job="docker-containers"} |= "restaurant-web"

2. Lọc request HTTP 200 dạng JSON:
{job="docker-containers"} |= "HTTP Access Log" | json | status == 200

3. Phát hiện lỗi hệ thống:
{job="docker-containers"} |= "error" or "ERROR" or "failed"

CHƯƠNG 7: TĂNG CƯỜNG BẢO MẬT (SYSTEM HARDENING)

  • Non-root Container: Web App chạy dưới tài khoản appuser (UID: 1001), không chạy bằng root.
  • Network Isolation: Tách biệt 3 mạng bridge, cô lập CSDL tuyệt đối.
  • Dropping Linux Capabilities: Cấu hình cap_drop: - ALL ngăn chặn can thiệp kernel.
  • Chính sách Mật khẩu mạnh: Độ dài trên 12 ký tự, quản lý qua .env.
  • Ẩn thông tin máy chủ: Cấu hình Nginx server_tokens off;.
